## AC-1: Código de aeropuerto con payload no se guarda ni se ejecuta
```gherkin
Given un email cuyo "City Pair" contiene un token no-IATA (p. ej. `<IMG SRC=X ONERROR=…> - STN` o `__PROTO__ - STN`)
When el usuario lo pega
Then la app no pide coordenadas para ese token y no lo guarda en _airports
And si _airports ya contiene una clave no /^[A-Z]{3}$/ (venga de localStorage o Firestore), la lista la muestra escapada y marcada "inválido", con ✕ que la borra por índice numérico, y el contador "· N" coincide con lo pintado
```

## AC-2: Estado almacenado manipulado no llega crudo a HTML ni a onclick
```gherkin
Given _ukdays, _cache, _excelData o _dayMap contienen una clave o valor manipulado (comillas, `<`, `');alert(1);//`)
When se renderizan UK Days (UK y "No UK"), Días guardados, Días solo-Excel y el calendario
Then cada argumento de onclick="f('X')" en el HTML resultante cumple /^\d{4}-\d{2}-\d{2}$/, /^[A-Z]{3}$/, /^\d{4}-\d{2}$/ o es una constante conocida
And ningún innerHTML contiene `<img`, `<script` ni `onerror=` sin escapar (sí puede contener `&lt;img`)
And los contadores (días, vuelos, meses) se calculan sobre la lista ya filtrada
And la clase CSS del calendario solo toma estados de la whitelist (off, stby, duty, sim, sd)
And el estado en memoria/almacenamiento no cambia por renderizar (las fechas inválidas ocultas dejan console.warn)
```

## AC-3: Claves reservadas o enormes del email no rompen Firestore
```gherkin
Given un email con líneas "__X__ : y", "a__b__c : y" o una clave de más de 500 caracteres
When se pega
Then esas líneas se ignoran al parsear y el día se guarda con el resto de campos
```

## AC-4: Sin regresiones y verificado en el iPhone
```gherkin
Given todos los harness existentes (11) + harness-seguridad.mjs
When se ejecutan

And el usuario confirma en el iPhone que pegar un email real, UK Days, calendario, aeropuertos y exportar CSV/Excel funcionan igual que antes
```
