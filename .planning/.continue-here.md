# Sesión de pausa — PilotLog CSV import debugging

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Adivinar formato de wizard sin verlo importar | Hicimos >15 commits cambiando separadores, headers, encoding sin tener evidencia concreta del comportamiento del wizard. Cada test 5+ minutos del usuario (cache, regenerar CSV, import, verificar). | blocking | Antes de tocar formato CSV: pedir 1) screenshot de error/resultado del wizard, 2) el CSV exacto que se importó (no asumir cache OK). No iterar a ciegas. |
| Confundir vías de import distintas | El usuario tiene 3 vías de import a PilotLog (native iOS EFB email parser, web wizard, desktop) con reglas distintas. Asumí que su screenshot "funcionando" era de la misma vía que estábamos depurando. | blocking | Antes de teorizar sobre por qué algo "funcionó antes": preguntar EXACTAMENTE cómo fue importado (qué app, qué archivo, qué flujo). |
| Asumir doc oficial = comportamiento real | La doc de CrewLounge dice DELAY acepta IATA numeric, FLIGHTLOG max 250 chars, etc. Realidad: wizard rechaza más cosas que la doc, persiste menos campos que el schema. | advisory | Tratar la doc como guía, no contrato. Validar empíricamente con cada importer. |
| 99-col canonical schema NO funciona en web wizard | El wizard tiene una whitelist más corta que el schema canónico del DB. Rechaza TAG_DELAY, TAG_APP, TIME_MODE, FUELPLANNED, INSTRUCTION/TRAINING. También rechaza DD/MM/YYYY (quiere ISO). | blocking | Si se vuelve a intentar bypass de wizard: NO mandar el schema completo de 99 cols — el wizard lo rechaza. |
